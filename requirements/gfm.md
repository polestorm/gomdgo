# Wymagania: rozszerzenia GFM

Źródło: GitHub Flavored Markdown 0.29-gfm, rozdziały oznaczone „(extension)”. Przykłady z tych rozdziałów są
testami wymagań (`TestSpecGFM`). Rozszerzenia GFM są domyślnie włączone; wyłącza je `Config.Disable`
(ADR 0007).

| Id | Wymaganie |
|---|---|
| GFM-001 | Tabela (`Tables`): wiersz nagłówka, pod nim wiersz ograniczników (`-`, opcjonalnie `:` z lewej, prawej albo obu stron) o tej samej liczbie komórek, potem wiersze danych. Nagłówkiem jest ostatni wiersz akapitu; wcześniejsze wiersze zostają akapitem. Co najmniej jeden z dwóch wierszy zawiera znak `\|`. Komórki rozdziela `\|`, skrajne są opcjonalne, `\\\|` daje znak `\|` także w kodzie w wierszu; treść komórki to treść w wierszu. Wiersz danych ma tyle komórek, ile nagłówek: brakujące są puste (do limitu z `GFM-008`), nadmiarowe pomijane. Tabelę kończy pusty wiersz albo początek innego bloku; wiersz tabeli nie jest kontynuacją leniwą. Wyrównanie kolumny trafia do atrybutu `align`; bez wierszy danych nie ma `<tbody>` (rozdział „Tables”). |
| GFM-002 | Lista zadań (`TaskLists`): element listy, którego pierwszym blokiem jest akapit zaczynający się od `[ ]`, `[x]` albo `[X]` i białego znaku, dostaje na początku akapitu wyłączone pole wyboru, zaznaczone dla `x`; znacznik znika z treści. Działa w listach zwartych, luźnych, numerowanych i zagnieżdżonych (rozdział „Task list items”). |
| GFM-003 | Przekreślenie (`Strikethrough`): tekst między dwiema seriami dokładnie dwóch tyld, z regułami serii lewo- i prawostronnych jak dla `*`; daje `<del>`; nie przechodzi przez granicę akapitu; serie innej długości są zwykłym tekstem (rozdział „Strikethrough”). |
| GFM-004 | Rozszerzone autolinki (`Autolinks`): w zwykłym tekście poza odnośnikami rozpoznawane są adresy zaczynające się od `www.`, `http://`, `https://`, `ftp://` (na początku wiersza, po białym znaku albo po `*`, `_`, `~`, `(`) z poprawną domeną, oraz adresy e-mail. Interpunkcja na końcu, niesparowany nawias zamykający i końcówka podobna do odwołania znakowego nie należą do adresu; `<` kończy adres. `www.` dostaje schemat `http://`, e-mail `mailto:`. Adres podlega liście dozwolonych schematów (`SAFE-003`), więc `ftp://` przy ustawieniach domyślnych zostaje tekstem (rozdział „Autolinks”). |
| GFM-005 | Filtr znaczników (`TagFilter`): przy `RawHTMLPass` w znacznikach `title`, `textarea`, `style`, `xmp`, `iframe`, `noembed`, `noframes`, `script`, `plaintext` (otwierających i zamykających, bez rozróżniania wielkości liter) znak `<` jest zapisywany jako `&lt;`; pozostały HTML przechodzi bez zmian (rozdział „Disallowed Raw HTML”). |
| GFM-006 | Przy ustawieniach domyślnych włączone są wszystkie rozszerzenia GFM. Każde da się wyłączyć osobno przez `Config.Disable`; składnia wyłączonego rozszerzenia jest zwykłym tekstem CommonMark. Z `Disable: GFM` wynik każdego przykładu CommonMark jest taki sam jak w specyfikacji. |
| GFM-007 | Opcje zgodności z parserem odniesienia, domyślnie wyłączone: `Config.SingleTilde` sprawia, że serie jednej i dwóch tyld są ogranicznikami przekreślenia (przy różnych długościach zużywany jest jeden znak z każdej strony, jak w wyróżnieniu; trzy i więcej tyld to tekst); `Config.TableAlignStyle` zapisuje wyrównanie kolumny jako `style="text-align:…"` zamiast `align`. Oczekiwane wyniki pochodzą z parsera odniesienia uruchomionego jako czarna skrzynka (ADR 0008). |
| GFM-008 | W jednym dokumencie wiersze tabel krótsze niż nagłówek są dopełniane łącznie najwyżej 100 000 pustych komórek; kolejne krótsze wiersze zachowują tylko własne komórki. Rozmiar wyniku jest dzięki temu ograniczony liniowo przez rozmiar wejścia plus stałą (ADR 0008). |
